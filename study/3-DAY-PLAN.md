# 3 天完整学习计划

前提：每天约 8 小时专注学习，另留休息时间。目标是能**讲清一条实际调用链、解释关键取舍、用源码或测试举证、识别评测局限**。每个时间块采用“读课程 35% → 追源码 35% → 口述/画图/答题 30%”。当前 macOS 只做源码级练习；Windows 运行项见 [部署说明](DEPLOYMENT.md)。

## 第 1 天：从用户输入到安全工具执行（第 1–8 章）

- **09:00–09:40｜建立地图。** 读根 README、本目录架构图和课程地图。写一张 10 节点调用链，标出 CLI、runtime、loop、client、registry、tool batch、session。
- **09:40–11:10｜第 1–2 章。** 跟 `cli.main → runtime._run_session → loop.run_turn`，画出“一个用户回合，两次模型请求”的时序。口述 system、历史、动态上下文的来源与刷新点。
- **11:20–12:50｜第 3–4 章。** 追工具注册、参数校验、`Read → Edit → 验证`。在 `tests/test_mvp_loop.py` 找到结果回流断言，在文件编辑实现里找读取基线与写入检查。回答“旧文唯一，为什么仍会拒绝编辑”。
- **14:00–15:30｜第 5–6 章。** 画出“模型参数 → Hook → 最终路径/参数 → 权限 → 执行”的顺序。再用 `client/sse.py` 与 `ChatAccumulator` 解释 SSE 事件与 tool call 拼接。
- **15:40–17:10｜第 7–8 章。** 做失败矩阵：限流、上下文过长、输出已暴露、工具结果未知、进程重启。为每项写“能否重试、需核实什么、记录在哪里”。
- **17:20–18:00｜闭卷验收。** 不看资料，5 分钟讲完整主链；回答 [面试演练](INTERVIEW.md) 第 1–5 题。错题回到对应章节，标明源码证据。

**当日交付物：** 一张时序图、一张失败矩阵、一段 3 分钟项目介绍。验收标准：能区分模型“建议动作”、程序“获准执行”、用户任务“有证据完成”。

## 第 2 天：长任务、并发与上下文（第 9–15 章）

- **09:00–09:30｜回顾。** 闭卷重画主链，解释 day 1 的一个未知结果场景。
- **09:30–11:00｜第 9–10 章。** 跟计划更新、后台 Shell、等待与取消。写清 task ID、run ID、进程终态、通知入会话的先后关系。
- **11:10–12:30｜第 11–12 章。** 跟用户补充输入、暂停、旧回调和子代理任务交接。画父子会话和工作树边界，说明何时并行真的有收益。
- **13:40–15:20｜第 13–14 章。** 用一组“assistant tool_calls + 两条 tool result + 长日志”推导安全压缩切点。说明摘要失败时为什么保留原文，以及如何凭 archive ID 回查。
- **15:30–16:40｜第 15 章。** 比较两次实际请求的稳定前缀、动态尾部、工具顺序；用基准文档解释输入缓存命中率与总费用的不同口径。
- **16:50–18:00｜闭卷验收。** 回答 [面试演练](INTERVIEW.md) 第 6–10 题，做一次 10 分钟白板：系统在“模型断线 + 工具结果未知 + 用户补充要求”时怎样恢复。

**当日交付物：** 后台任务状态图、压缩与归档图、缓存成本口径说明。验收标准：每条恢复路径都有可检查的事实来源，不把“请求超时”直接当作“没有执行”。

## 第 3 天：记忆、扩展、评测和模拟面试（第 16–21 章）

- **09:00–09:30｜回顾。** 口述主链与 day 2 的三种故障；补齐不会解释的源码点。
- **09:30–11:00｜第 16–17 章。** 对比启动记忆、任务召回、受控学习。写一个旧经验条目：适用条件、当前来源、验证证据；再写一个因代码版本变化而不能直接采用的反例。
- **11:10–12:30｜第 18–20 章。** 画 Skill、MCP、Hook 三条接入路径：谁提供流程/工具/时点，谁最终执行，权限在哪查。分别回答“远端写入回包丢失”和“Hook 改路径”。
- **13:40–15:00｜第 21 章与基准。** 读 `docs/benchmark/README.md`，写 1 页实验设计：固定模型、任务、版本、预算、试次数，记录通过率、耗时、token/费用与失败类型；列出原项目 71/89 和 5 题缓存对照的解释限制。
- **15:10–16:20｜项目复盘。** 速读 [工程补遗](ENGINEERING-EXTRAS.md)，再用一页纸重建整体架构：入口/TUI、主循环、工具、权限、持久化、上下文、扩展、观测与评测。对每个设计给出一个“为什么”和一个“条件变了如何改”。
- **16:30–17:30｜模拟面试。** 20 分钟项目介绍与追问，20 分钟故障场景，20 分钟评测/取舍。用 [面试演练](INTERVIEW.md) 的评分标准自评。
- **17:30–18:00｜补洞。** 只复习未达标的 3 个点，并把具体源码、测试或文档链接写入个人面试提纲。

**当日交付物：** 一页架构图、一页实验设计、一次录音或文字模拟面试。验收标准：能独立回答“项目做了什么、关键机制如何实现、你亲自验证过什么、哪些结论不能外推”。

## 每章统一学习模板

1. 用一句话说要解决的故障或风险。
2. 指出模型、Agent 程序、工具、用户各自的职责。
3. 从章节链接追到一个实现函数和一个测试/证据。
4. 用具体输入、状态转移、输出举例。
5. 讲一个边界条件和失败后的处理。
6. 用 90 秒口述，不照读文档。

三天计划保证知识覆盖，不保证 21 章每个细节都能一次记住。优先把主链与四类高频追问（工具安全、恢复、上下文、评测）讲扎实。
