# 第 1 章复习卡：一次查价里的 Agent Loop

对应原文：[一次查价里的 Agent Loop](../../docs/learning/revised/task-loop.html)。本卡按 `v2.0.0` 的课程案例整理，面试时用自己的话说，不必背代码行号。

## 一句话记住

**模型提出要做的事，Agent 程序负责执行；程序把真实工具结果交回模型，模型才能继续回答。** 用户只问一次，中间可以有多次模型请求和工具往返。

## 把查价过程讲成人话

用户问“普通价现在打折吗？”模型手里还没有价格文件，于是第一次请求返回 `Read({"path":"prices.mjs"})`。这里模型只是**提出读取请求**，真正打开文件的是本地程序。程序读到 `return count * price;`，把它作为工具结果存进会话，并和原调用 ID 配对。第二次模型请求带上这条结果，模型才有依据说“普通价没有打折”。

```text
用户提问
  → 第 1 次模型请求：模型要求 Read
  → Agent 校验并执行 Read，保存真实结果
  → 第 2 次模型请求：模型看到文件原文
  → 模型给出完整答复，没有新工具请求
  → 本轮结束
```

你刚才的回答“模型没有拿到工具调用之后的结果”是对的。再补一句就更像面试回答：**终端显示给人看，与下一次请求发给模型，是两条不同的通道。** 如果只打印了公式，却只给模型“读取成功”，模型仍不知道是否打折。

## `turn`、模型请求、任务完成是三回事

- **一个用户回合（turn）**：Agent 接手这次用户输入，到 `run_turn` 交还控制权。查价案例里是一个 turn。
- **模型请求**：这个 turn 里可以发多次。查价案例里第一次让模型决定读文件，第二次让模型依据结果回答。
- **正常结束**：在完整、有效的模型响应中，没有待执行的工具调用，程序保存回答并返回 `complete`。
- **用户任务完成**：还要看回答是否有足够证据。如果文件找不到，模型回答“请告诉我路径”，程序也能正常结束，但查价还没完成。

源码对照：[`agent/loop.py:run_turn`](../../src/ruocun/agent/loop.py) 构造每次请求、保存 assistant 消息、判断 `if not calls`、派发工具、把工具结果加入 `session.messages` 后继续循环；[`tools/tool_batch.py`](../../src/ruocun/tools/tool_batch.py) 给工具回复保留 `tool_call_id`。[`tests/test_mvp_loop.py`](../../tests/test_mvp_loop.py) 检查下一次请求确实带着原调用编号和读取结果。

## 为什么“编辑成功”还不等于“需求完成”

新回合里，用户要把普通价改九折、会员价不变。`Edit` 报成功，最多证明目标文件写入了新公式。直接调用两个计价函数得到普通 180 元、会员 200 元，证明这两个函数在给定输入下算对了。若用户真正关心**订单预览**，还要从预览入口检查；页面可能仍走旧函数，最终显示 200 元。

遇到“终端预览还是 200，助手却说已变 180”时，先按预览工具的 `tool_call_id` 查结果是否进入下一次模型请求。没进入，问题在结果回流；进入了，再查模型解释与页面实际调用路径。不要直接断言模型忽略了结果。

## 原文面经与设计题（7 题）

1. **用一次工具调用讲 Agent Loop。** 模型先根据现有信息提出 `Read`；程序实际读取、保存结果；下一次请求把结果交给模型；模型再决定继续用工具还是给最终答复。查价是一个 turn、两次模型请求。
2. **用户只说一句，谁让模型继续？** Agent 主循环负责。工具执行和结果回流之后，它再次请求模型，用户无需说“继续”。
3. **Agent 怎样判断循环该停？** 完整有效的模型回答没有工具请求时正常收尾；取消、错误、预算或显式轮数上限也可能使程序停止，但含义不同。
4. **工具调用失败怎么处理？** 保存真实失败原因并回给模型，例如“文件不存在”；模型可重新定位或问用户。不能把失败写成已经读到了内容。
5. **查价发了两次模型请求，算几个 turn？** 一个用户回合、两次模型请求。工具往返属于同一次用户任务的处理。
6. **程序把价格打印在终端，却把旧历史原样发回模型，缺什么？** 缺真实工具结果及对应调用关系。模型看到的下一次请求没有价格事实。
7. **改价已退出循环，还核对什么？** 核对用户能观察到的入口和全部要求，例如同一订单预览下普通 180、会员 200；函数单测通过不足以证明页面入口生效。

## 面试官可能继续追问

1. **模型第一条回复已有文字“我先看一下”，为什么不马上结束？** 因为同条回复还带工具调用；文字是进度说明，读取动作尚未完成。
2. **返回空文字、无工具调用，是正常完成吗？** 不是。代码会有限次重试空响应，连续为空则失败退出。看 `agent/loop.py` 的空响应处理。
3. **网络在回答中间断开，恰好没有工具调用，能套用 `if not calls` 吗？** 不能。要先确认响应完整；部分响应会保留已收到的内容并报告失败，不派发未收齐的工具。
4. **模型反复要求读同一文件会怎样？** 正常停止条件一直不成立。用户可取消，也可显式配置轮数上限；到上限应报告“轮数限制”，不能假装任务完成。
5. **为什么要保存 assistant 的工具请求及工具结果两条消息？** 下一次请求要知道“谁请求了什么”和“对应返回了什么”；`tool_call_id` 负责配对，避免多个调用结果串线。
6. **查价结果与订单预览结果冲突，先查哪里？** 先看预览工具结果是否进入模型历史，再追页面实际调用链；把“工具没回流”和“页面走旧入口”区分开。

## 90 秒面试表述

“若存的核心是一个 Agent Loop。用户问普通价是否打折时，模型第一次并不知道价格文件内容，只能请求 `Read`。本地程序校验并执行读取，把原文和调用 ID 作为工具结果存进会话，再发第二次模型请求。模型这时才有依据回答。只要完整响应里还有工具调用，循环就继续；没有调用时，程序正常结束本轮。但我会把‘循环结束’和‘用户需求完成’分开看。比如改价后，还要沿订单预览入口验证普通价和会员价，不能只凭 `Edit` 成功。”
