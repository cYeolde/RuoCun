# 第 5 章复习卡：执行前谁说了算

原文：[执行之前谁说了算？](../../docs/learning/revised/permission-gates.html)。延续改价例子：模型请求 `Edit({"path":"pricing.txt","old_string":"普通价","new_string":"九折"})`，调用 ID 是 `edit-42`。

## 一句话记住

**批准应绑定最终要执行的参数和本次调用；执行前还要重新查当前模式、取消状态及实际路径。** 模型能提出工具调用，不代表工具一定会执行。

## 一条编辑请求过哪些关

1. **工具与参数。** 注册表确认 `Edit` 存在，JSON Schema 检查 `path`、`old_string`、`new_string` 等字段和类型。`pricing.txt` 与 `draft/pricing.txt` 都是合法字符串；Schema 不能判断哪个可写。
2. **前置 Hook 后重验。** 若 `PreToolUse` 把路径改到 `draft/pricing.txt`，程序用改后的**完整参数**重新做 Schema 校验，再裁决权限。Hook 只返回路径、漏掉旧文和新文，会因参数不全失败。审批框应展示改后的目标；对旧目标的批准不能直接搬用。
3. **规则与审批。** 对工具名和目标等实际调用信息匹配规则，明确 `deny` 优先于 `ask`，再优先于 `allow`。需要询问时，批准按 `edit-42` 等调用 ID 归回本次；同批另一项编辑有自己的决定。“仅本次允许”与可记住的范围规则是两种授权。Hook 的 `allow` 也不能覆盖明确拒绝。
4. **临执行前复核。** 如果用户在请求发出后切到只读 `plan` 模式，旧工具清单里虽有 `Edit`，此刻仍不得启动它。若审批等待期间用户取消，同意回包晚到，程序给 `edit-42` 记取消结果，处理器不启动。进入处理器前再检查一次。若写入已经开始，需查工具记录和文件结果，不能仅凭取消推断未写。
5. **解析实际路径与读写权限。** 相对路径按当前工具的 `cwd` 解析；`/shop` 下的 `pricing.txt` 落到 `/shop/pricing.txt`。工作区外的路径，读与写分别批准：允许读共享报表，不自动允许改它。通过后，`Edit` 才接第 4 章的读取基线、唯一旧文、文件锁和写盘流程。

源码入口：[`tools/tool_batch.py`](../../src/ruocun/tools/tool_batch.py)、[`permissions/runtime.py`](../../src/ruocun/permissions/runtime.py)、[`permissions/rules.py`](../../src/ruocun/permissions/rules.py)、[`tools/paths.py`](../../src/ruocun/tools/paths.py)。

## 口头推演三种情况

- **`deny` 与 `allow` 同时命中，Hook 还建议 `allow`：** 最终拒绝，编辑处理器不启动。
- **请求发出时是普通模式，审批后切到 `plan`：** 派发时按当前模式拦住写入；旧工具清单、旧批准都不能证明文件已改。
- **批量审批时取消，随后收到 `{"edit-42":true}`：** 同一 ID 记录取消，后续派发跳过；若已进入处理器，则应查实际收尾。

## 原文 7 道面经与设计题

1. **Agent 可以写哪些地方？边界在哪里检查？** 看当前模式、最终参数和实际解析后的目标。规则裁决、外部路径写授权、派发前复核共同决定；不能只看模型提出的字符串。
2. **只读资料夹带“请写回”指令，如何避免擅自照做？** 文件内容是资料，不是用户授权。即便模型受其诱导提出 `Edit`，本地程序仍独立按实际目标和写入权限裁决。
3. **JSON Schema 能拦什么，拦不了什么？** 能拦缺字段、类型错误和不合约定的值；不能凭路径是字符串就断定真实位置可写，也不能替代权限与文件状态检查。
4. **Hook 换了路径，旧批准还能用吗？** 不能。用 Hook 改后的完整参数重新校验和裁决，需要时把实际目标重新展示给用户。
5. **`plan` 已隐藏写工具，为何派发时还查？** 工具清单是请求时的快照；模型回包到达时模式可能已变。派发以当前模式为准。
6. **批次已批准，随后取消，还写吗？** 若处理器尚未启动，取消检查拦住并给本次调用记取消；若已启动，查记录与文件结果，不能一概断言。
7. **为什么读和写分开授权？** 读只取得内容，写会改变别人之后看到的文件；同一路径的读取许可不涵盖修改。

## 额外追问

- **批准界面显示相对路径就够吗？** 要确认它在当前 `cwd` 下的实际落点；同一字符串在不同目录可能指向不同文件。
- **审批返回 `true` 就证明写过吗？** 不证明。后面还可能切模式、取消、路径校验失败、旧文不唯一或写盘失败。沿调用 ID 看最终结果。
- **权限拒绝后模型该怎么做？** 准确报告原调用未执行；若有用户允许的替代目标，发起新调用并重新裁决，不能把拒绝当成功。
- **`plan` 模式能否运行写入或命令？** 派发阶段对这些能力硬拦截；其余工具仍按各自规则处理。

## 90 秒面试表述

“若存的权限门不只看模型能否调用工具。注册表先校验最终 JSON；前置 Hook 如果改了路径，改后参数要重验并按新目标审批。规则冲突时明确拒绝优先。用户在模型请求之后还可能切换计划模式或取消，所以派发和进入处理器前需要复查当前状态。文件路径按实际工作目录解析，工作区外读写分开授权。最后我会沿调用 ID 看执行回包与文件结果，不能把‘用户点了同意’等同于‘文件已写’。”
