# 面试演练：问题、答题骨架与评分

先闭卷回答，再展开课程章末“面经自测”核对。不要把未在当前机器实际运行的结果说成自己复现的结果。每题按 0–3 分自评：0=不知道；1=只会概念；2=能给项目源码位置和具体例子；3=还能说清失败边界、取舍及验证证据。满分 45；达到 36 且第 1、2、4、6、10、15 题均不少于 2 分，可进入模拟面试。

1. **3 分钟介绍若存。** 答题骨架：Python 终端 Coding Agent；CLI 装配会话，主循环向模型请求、执行获准工具并回流结果；有持久会话、压缩归档、记忆、扩展与评测。说明项目是 Windows x64/CPython 3.11 发布目标；个人已完成的验证与原作者测评明确分开。证据：`cli.py`、`agent/runtime.py`、`agent/loop.py`、根 README。
2. **一个 turn 为什么能有多次模型请求？如何停？** 工具调用是中间动作，程序要把结果加入历史后继续请求；完整响应且无调用才走正常结束。另有取消、预算/轮数、压缩失败等退出。证据：`agent/loop.py:run_turn`，课程第 1 章。
3. **模型说要用 Read，谁真正读文件？** 注册表给模型工具描述；本地解析并校验参数，权限与模式通过后才执行，结果带 `tool_call_id` 回流。证据：`tools/registry.py`、`tools/tool_batch.py`，第 3 章。
4. **为什么 Edit 的旧文仍唯一却要拒绝？** 唯一匹配不保证读后文件没被人改；基线变化要重新读取以保留并发修改。成功写入后还须沿实际入口做回归检查。证据：`tools/edit_file.py`，第 4 章。
5. **Hook 改了工具目标路径，原批准能沿用吗？** 批准绑定最终执行参数与目标；前置 Hook 改参数后重新检查权限，旧路径的同意不能替代新路径的同意。证据：`hooks/hooks.py`、`tools/tool_batch.py`，第 5、20 章。
6. **模型流式输出一半断线，何时可重发？** 区分仅收到网络字节、已向用户暴露输出、已形成工具调用；根据已提交/可见状态选择重试、保留部分回答或停止。不能把半截 tool call 当完整参数执行。证据：`client/sse.py`、`client/resilient.py`，第 6、7 章。
7. **工具超时但可能已写入，怎样避免重复？** 执行前保存意图和最终参数，超时后按调用编号查原运行与外部事实；确认完成才记完成，未知则保留待核实，不能盲目再调用。证据：`session/durable_store.py`、`session/recovery.py`，第 8 章。
8. **后台测试已运行，为什么 TaskWait 不等于重新执行？** 同一运行有身份和日志；等待关注该 run 的终态与输出，取消请求也需要终态确认。通知进入会话后要记录已消费，避免重投。证据：`tools/managed_shell.py`、`agent/background_delivery.py`，第 10 章。
9. **用户中途补一句话会发生什么？** 先被终端/调度层接收，到了安全边界才进入下一次模型输入；旧回调不能盖过新一代状态，已启动的命令和待审批选择各有处理。证据：`agent/session_scheduler.py`，第 11 章。
10. **上下文太长时如何压缩又保留可追溯性？** 预算包含消息、工具与输出余量；先裁长日志，再摘要早期对话；调用与结果成组，摘要和原文索引事务提交后切换；可用 `ArchiveRead` 按 ID 回查。证据：`agent/compact.py`、`agent/context_runtime.py`、`tools/archive_read.py`，第 13、14 章。
11. **缓存命中率高为什么仍可能更贵？** 费用还取决于未命中的输入、输出 token、模型价格与试次；稳定前缀只是提高复用机会，实际命中需读服务端用量。证据：`session/cache_audit.py`、基准文档，第 15 章。
12. **长期记忆怎样避免旧经验误导当前任务？** 检查来源版本和适用条件；旧经验用于提出要核对的假设，实际结论以当前代码和测试为准；自动学习默认关闭，受控开启才提炼。证据：`memory/validate.py`、`agent/controlled_learning.py`，第 16、17 章。
13. **Skill、MCP、Hook 各是什么？** Skill 是按需加载的流程说明；MCP 带来外部工具/资源及连接；Hook 在工具前后执行规则或变换。三者都不能绕过最终工具权限和结果核实。证据：`skills/`、`mcp/`、`hooks/`，第 18–20 章。
14. **什么时候用子代理？** 能独立核查且有明确交付物的任务适合拆；需说明工作树/上下文边界和父子结果汇总，避免并行写同一资源。证据：`agent/fork_agent.py`、`agent/worktree.py`，第 12 章。
15. **如何证明一次改动提升了 Agent？** 固定任务、模型、版本、配置、预算与试次；比较任务结果、失败类型、耗时与 token/费用；查第一次行为分叉。原项目 71/89 是历史自测，5 题缓存对照每方每题一次，不能据此断定普遍优势。证据：`docs/benchmark/README.md`，第 21 章。

## 追问时的回答格式

“场景 → 入口/状态 → 关键实现 → 可见证据 → 失败边界 → 取舍”。例如问恢复：先界定是模型请求断线还是工具副作用不明；指到 `client/resilient.py` 或 `session/recovery.py`；说清何时可重试、何时必须先查事实；最后说明本机只完成源码核对，尚未在 Windows 上复现真实运行。
