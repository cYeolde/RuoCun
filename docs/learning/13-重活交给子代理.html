重活交给子代理

上下文、能力、消息与工作树隔离

用一次价格实现调查和独立复核，看清任务、状态、目录和执行权怎样从父代理交给子代理。

01

约好在独立目录检查，建不出来还能继续吗？

上一章用任务 ID 追到一次真实运行。这次后台结果来自另一个自己会问模型、用工具的执行者，也就是子代理。主代理先派一个子代理找折扣入口，再派另一个试改并复核。父目录 /shop 的 pricing.py 刚调到 90，还未提交。复核员要求 isolation="worktree"，即由 Git 基线 100 在另一个目录展开工作文件。它一启动就调用 Read({"path":"pricing.py"})，对照两个目录：会读到哪个价格，后续 Edit 会落到哪？

首读自检 · 两次 Read 分别指向哪个文件？哪个试改会动到父任务正在写的文件？

工作树成功时读的是 /review/pricing.py，值为 100，试改写向新树。退回时读的是 /shop/pricing.py，值为 90，试改会碰父文件。父目录未提交的 90 需要另行提供给复核员，才可能在隔离目录复核该版本。

右边是有问题的替代做法。RuoCun 碰到确认的创建失败，会在父会话回报“子代理未派发”。创建结果未确认时则保留现场。独立模型历史能避免把两趟调查混在一起，隔离试改还须核实真实目录。

02

独立会话、读取状态与角色能力

2.1 用明确交接材料替代整段调查历史

定位员的输入可以很短：“定位会员折扣的生效条件，返回入口、实现、关键用例位置和一处未核实的假设。”假设它读了十份文件，父代理只需接回能验证的报告。下表是子代理可能形成的报告结构。让主会话根据路径判断应读哪里，比让主会话先接收十次全文 Read 更省窗口。

示意报告 · 定位员应交出可核对的线索
材料示意内容父代理如何消费
入口与实现checkout.py 调用 pricing.py打开对应实现确认条件分支
覆盖范围现有用例只覆盖普通会员找出资格边界还缺哪组输入
未决问题过期会员策略待确认父代理查需求或补充指令

普通派发创建新的 Session，构造子角色的 system，加入本次任务文字，以及该角色配置的初始提示、已经载入的预置技能正文。默认取父执行相关的目录和项目材料，用子角色的工具集合；模型可按请求覆盖、角色配置或继承路径选定。父历史如果需要整个接着用，存在下节的 Fork。

2.2 读过文件的记录和待办各自建立

src/ruocun/agent/run_agent.py · 第 318–330 行

这段代码在创建子会话后构造新的 ToolContext。父代理读过 pricing.py，那次读取的文件版本只登记在父执行；子代理的 readFiles 和 readMeta 从空开始，待办、未核实写入也各自维护。复用父记录会让子代理凭另一趟的读取证据判断自己的编辑条件，文件可能早已变化。「共享磁盘时，每趟执行仍要建立自己的读取基线」。工作树条件另管写到哪个目录。

工具表按角色的允许和拒绝名单过滤。后台任务还有允许工具名单，计划模式再滤掉写入、执行及 MCP 工具，父级为 plan 时子级仍为 plan。普通子代理的工具表和分派入口限制再开子任务，工具处理器也检查深度。提示词写“只做定位”可以减少误判，工具表和执行边界给这句话提供实际约束。

2.3 装配角色资源，确认启动上下文

有些工具由独立的服务程序通过 MCP 提供。例如复核角色可以有自己的文档查询连接。装配只连接该角色声明且配置存在的服务，连接跟着这次执行打开和关闭。换后台接手者时，重建连接后还要核对之前保存的工具定义和可见集合。定义已变时拒绝交接，避免复核员途中拿到意思不同的同名工具。

第 8 篇已经见过工具调用前可运行的 Hook。子执行也有自己的事件时点。通过准入后可以触发 SubagentStart；若该规则附加了信息，先把它写入子会话的 system 消息并保存，保存未确认会停止第一次模型请求。正常收尾走 SubagentStop，结果未确认时保留现场。

src/ruocun/agent/agent_hooks.py · 第 40–49 行

专属连接怎样重建见MCP 接入，生命周期回执及其他事件见Hooks 执行规则。

03

Fork 的父历史快照与工具配对

普通派发只给子会话一份新任务。若定位讨论已经积累必要背景，可以用 fork=true，即按父模型这一轮实际拿到的配置和对话生成子会话快照。它承接父模型和权限模式，复制合适的历史，并使用发出请求时冻结的工具定义和激活状态。参数试图另行覆盖 model、mode 或显式隔离方式时会被拒绝。子任务说明追加在末尾，告诉模型这次要做哪件事。

示意 · 子代理第一次请求发出时手里有什么
候选记录当前能看到的回包
父历史中的 assistant 请求 Read r1role=tool，tool_call_id=r1
父历史末尾 assistant 请求 Agent a2a2 还在执行，父会话尚未收到对应 role=tool
要追加给子任务的 user 消息说明本次只复核会员折扣，可附带待执行调用的占位文字

若把父历史照原样复制，子代理第一次请求就带上一个欠回包的 a2。但 a2 必须等子代理执行后才有结果，靠等父会话先补齐，双方会互相等待。只留这条助手消息也无法获得合法配对。

src/ruocun/agent/fork_agent.py · 第 39–45 行

代入两项调用，paired_ids 里只有 r1。它的助手消息整条保留，a2 所在的助手消息整条过滤。最后留下 r1 与它的工具结果，再接子任务的 user 消息。占位文字给模型解释为什么没看到回包，协议配对仍由 role=tool 判断。「Fork 可以继承已配对的工具历史，触发自身且欠回包的助手消息要先让开」。若该助手消息还含其他调用，这条未完全配对的消息也不会分拆复制。新子会话核对其可见前缀与选中的父历史来源一致，方便原文溯源。工具配对的要求同时决定长会话能从哪里切，见完整工具组与压缩切点。

04

工作树创建与成果保留

4.1 只有核实目录才能派发

当复核需要写入隔离目录时，工作树以 Git 基线创建自己的文件副本。父目录未提交的改动不在该工作树的起始版本中。若希望独立复核某份变更，任务要给出可核对的提交或其他已确认的材料。remote 当前也在同一台机器的 Git 工作树中执行。工作树的承诺是按指定目录隔开工作文件，其主机和系统沙箱约束另有来源。

src/ruocun/agent/run_agent.py · 第 436–451 行

比如 Git 找不到有效基线，直接创建失败可转成工具错误，父代理可检查仓库条件后重新提交。若 git worktree add 已经调用、随后 Git 登记或 HEAD 身份无法确认，工作树模块抛出未知写入异常，保留现场供核实。「要求隔离的任务要等实际目录核实后才派发」。切回原目录虽然能得到一份报告，但它已经无法回答用户要求的隔离复核问题。

src/ruocun/agent/worktree.py · 第 267–277 行

完成后，清理前先释放子代理 MCP 连接使用的工作目录。干净且核实属于本次执行的工作树可以清理。如果基线到当前 HEAD 多出了提交，或者工作目录有改动，清理会保留分支与目录，报告支持主代理后续检查和合并。提交检查直接比较本地 Git 历史。失败分支的输出也可能指向保留的目录，此时先分辨做到了哪一步。

05

中途通信、完成报告与前后台交接

5.1 普通进度只更新，需决定的事项进入交付队列

定位员在后台发现过期会员规则不明确，可以用 MessageParent 发 kind="attention"，请父代理在安全边界处理。“已找到定价入口”之类的进度用 kind="progress"，它更新进度，无需唤醒等候中的父代理。结束事件另行发布。消息的身份来自运行和工具调用，旧 run 已停止时拒收迟到消息。

src/ruocun/tools/message_parent.py · 第 24–35 行

父代理查到了确认条件，可用 TaskSend 对活跃任务追加“过期会员按普通价处理”。管理器确认这是正在执行的非 manual 任务，按发送工具的身份持久化收件箱。同一发送身份重到且内容相同时可确认，内容发生变化则拒绝。子代理在后续模型边界把待处理消息保存到自己的历史，再继续请求模型。如果子代理已结束，向原运行追加中途消息会失败，需要按工具支持的明确后续执行流程处理。结束报告由执行器结算，可能是完成输出、失败伴随部分输出、取消或结果未知。拿到报告后仍要根据原任务核验。

src/ruocun/agent/tasks.py · 第 396–416 行

5.2 从已保存的子代理历史取回报告

压缩后，模型当前历史里的消息下标可能变化。程序保存任务开始处的原文位置，按运行 ID 从该位置分页读取。同步子代理完成时，从这段历史取最后一条非空助手正文，再确认完成结果。后台管理器在同样的原文范围取消息，按退出原因结算。后台失败时可能返回已有的部分正文，确认工具结果有疑问时交由恢复流程核实。

src/ruocun/agent/resume_agent.py · 第 74–88 行

5.3 等到配对边界才换接手者

第 7 篇的Shell 转后台交接的是同一个活进程的控制。模型循环的交接则从一份已保存的进度接着跑。前台先到消息配齐的边界保存并停止，再由后台执行拿着旧执行来源、剩余轮次和输出起点启动，主会话接到后台任务 ID 后可等待它。目录无法重新核实，或新接手者恢复的 MCP 工具定义发生变化，就停止交接。这样同一项工具不会因为两边同时继续而被执行两遍。

06

失联后的显式继续

假如复核员失联，旧运行成为 interrupted。人可以在核对未决工具和附件后明确给出继续指令。系统核实原模型、角色定义与版本、工作目录、消息、权限和预算，Fork 额外需要父上下文及精确工具等材料。恢复申请先提交许可，再为同一任务登记新的 run。新执行器核对决策、身份和持久化的运行回执后才启动。相同恢复许可重到时，到已有运行查状态。

src/ruocun/session/recovery.py · 第 177–193 行

如果旧复核员可能已经提交改动，但本地没有拿到结果，要先凭现有 Git 记录、文件和未决操作证据判断发生了什么。「继续一项任务要登记新运行，旧副作用留在原运行核实」。这使“继续收集证据”仍可执行，而已经可能发生的写入保留清晰来源。参见副作用意图、结果确认与恢复。

07

学习效果检测

7.1 判断状态继承、隔离与父子通信

1．父代理已读过 pricing.py。定位员可直接依赖这次读取做 Edit 吗？

展开详答

子执行的读取基线从空开始。即使 Fork 历史含那条 Read，子执行自己的 ToolContext 依然重新建立。应按实际工具契约重新读目标，并检查角色是否具备写权限。

2．Fork 的最后一条父调用尚未返回，子历史能保留完整该条调用吗？

展开详答

缺回执的助手调用消息会从请求副本中滤除。占位文字属于用户消息，不能充当工具回执。较早完整配对的组继续提供背景。

3．后台子代理要请父代理选择产品条件，应该用哪个消息种类？

展开详答

attention 会请父代理在安全边界处理。progress 适合汇报已完成搜索等非阻塞进展；需要等待具体决定时，父方的补充走 TaskSend。

4． 主目录尚未提交的新阈值是 5，Git 基线为 3。复核员在确认创建的独立工作树里运行测试，回报退出码 0，但报告没有注明所读阈值。能把结果交付为“新阈值已验证”吗？请指定一次最小的补查。

展开详答

工作树按 Git 基线创建。现有结果只确认复核员那份工作树上的测试退出成功。先请它读回实际测试目录里的阈值并核对版本。若仍为 3，需把拟验的变更明确带到复核目录，确认是 5 后重跑针对新阈值的断言。

08

模拟面试官提问

8.1 Agent 开发实习

独立核心题

为什么用子代理来定位一段陌生代码？任务应怎样写？

展开参考回答

我会让子代理把探索过程留在自己的会话里，父代理只收结论、文件位置和未核实项。任务给清楚要查的入口、可用操作和报告格式，这样父代理拿着报告就能立刻核查。

普通子代理每次建立 Session 和工具状态。角色表约束可用能力，父程序再根据报告判断是否已达到用户要求。

重点追问链

怎样安排一次独立复核？

展开主问回答

我先确定复核要看的版本和可执行的检查，再给独立会话提供明确报告目标。

追问 1 如果复核员为确认问题需要试写文件呢？

展开追问 1 回答

明确派发工作树隔离，提供可核对基线和允许动的范围。

追问 2 如果父代理的变更尚未提交呢？

展开追问 2 回答

新工作树从 Git 基线出发，要明确提供实际待复核材料，拿错误版本的检查结果没有说服力。

8.2 Agent harness 岗位

独立核心题

前台子执行转后台时怎样避免两方同时执行工具？

展开参考回答

请求转后台先登记，前台跑到配对边界保存，领取交接后停下。新执行拿着来源检查点、剩余轮次和目录身份重建资源，确认新的后台运行后才能继续。

前台安全边界、后台运行登记以及 MCP 重绑定分别约束了历史、执行权和工具现场。

重点追问链

子代理失联时为什么不能直接执行它最后的调用？

展开主问回答

最后的副作用也许已经发生。我会先查该执行的原记录，再用基于证据的显式恢复许可开启新 run。

追问 1 如果缺其中一份历史附件或原角色版本呢？

展开追问 1 回答

先补齐或核实材料。继续入口会检查旧执行所需现场，避免当前默认配置覆盖旧约束。

追问 2 如果新许可提交后反馈中断，同一指令又发了一次呢？

展开追问 2 回答

用决策身份查原回执和已登记新 run；不为同一许可再启动一次。

09

这一篇带走什么

子代理在独立会话和实际能力边界内处理分派工作，父代理通过可追踪的报告、中途消息和必要的交接接回结果。

  • 适合委派的调查要提前定义可核查的报告。让中间搜索留在子会话，父会话沿关键位置验证。
  • 分开看状态隔离和目录隔离。历史、读取基线和工具表由子执行建立，承诺工作树隔离时先验证 Git 登记和实际工作路径。
  • 换执行者前，先在安全边界保存并移交控制权。需要重新连接专属服务时核对定义与可见能力。
  • 失联后先核旧副作用，再以显式决策登记新的继续运行。让旧证据和新运行分别有身份。

Fork 挑的是子代理可以继承的完整历史。下一篇用同一个调用与回包约束检查父会话的压缩切点，决定哪几条必须一起留在请求中。
