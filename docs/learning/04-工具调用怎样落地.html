02

工具定义与模型可见接口

2.1 模型用公开定义填参，执行器用注册对象派发

模型需要工具名、用途和参数形状，程序另外需要派发函数、审批级别和调度信息。RuoCun 用一个 Tool 对象集中描述它们，由注册表按名字找回。增添工具后，派发器可以复用同一套校验与反馈流程。

src/ruocun/tools/types.py · 第 106–118 行

字段类型及必填性用途
name必填字符串模型点名，注册表按名查定义。
description / descriptionEn字符串，前者必填，后者可省说明用途。英文请求优先用已有英文描述。
schema / apiParameters字典，前者必填，后者默认 None用前者校验。若明确给了后者则向模型公布它，否则从前者转换。
capability必填，可为 read、write、exec、plan 或 network参与清单过滤、权限和调度。
approval / checkPermissions前者必填，可为 auto、suggest 或 required。后者是可选函数approval 是定义层标签。实际派发的权限引擎会读工具的 capability 和 checkPermissions，结合本轮策略与授权裁决。
handler必填异步函数收到参数对象及 ToolContext，返回文本。
shouldDefer / persistentEffect布尔值，均默认 false延迟公布，或声明持久副作用以便独占执行和记账。

正常清单会按规划模式、MCP 可见状态和延迟激活过滤。清单只公布名字、描述和参数，派发仍用注册对象。分叉需同时保存这轮实际发出的定义及其本地处理器。forkSnapshot() 按名字配对，找不到定义时无法构成快照，避免可见与可派发脱节。独立注册表见子代理篇。

03

参数校验与执行上下文

3.1 参数错误在发生处被分辨，再以原 ID 回流

只回“工具失败”，模型还得猜是填错、没权限还是文件坏了。validate() 先用 JSON 解析把参数字符串变成数据，拒绝 NaN 这类非法常量，再用内置 schema 子集查类型、必填字段、额外字段及范围。file 传进来时，先报缺少 path，随后列出可接受字段。执行器用原调用 ID 组装错误消息。

src/ruocun/tools/tool_batch.py · 第 175–193 行

整数校验接受 2.0，再规范化为整数 2。字符串 "2" 和布尔值 true 都不能当行号。若系统配置了能在执行前改参的扩展 Hook，校验使用改后的值。路径权限和磁盘读取也各有自己的失败反馈。「用形状校验解释该怎么填，用权限裁决判断这次能不能做。」具体裁决见执行裁决篇，远端工具定义和本地校验的分工见MCP 篇。

3.2 Read 的图片槽独立，文本基线回到会话

ToolContext 是程序交给处理器的运行上下文。模型给 Read 的参数只有文件路径和可选行段，程序还要从上下文取得实际目录、取消信号和授权服务。处理器可以用它保存程序自己的状态，例如路径、读取前的修改时间和大小，供后续 Edit 核对。模型通过工具消息看到的是带行号的文本。

src/ruocun/tools/read_file.py · 第 30–43 行

如果两次并行 Read 都往同一个槽写图片，一个调用回来取图时就可能取到另一张。批次给每个 Read 单独的 currentImageData，按各自调用 ID 回填。读线程独立记录的文本基线则回业务循环合并到共享映射，后续 Edit 可以读取。状态需不需要共享取决于后面谁来用它。

延迟工具发现

4.1 ToolSearch 让下一次请求看到完整定义

RepoMap 用来给模型一份仓库结构摘要，适合一开始还不知道该读哪些文件时使用。它已注册，正常清单仍会过滤未激活的 shouldDefer 工具。每轮都发送所有定义会挤占模型可以用来读历史与材料的空间。延迟公布需要先多一次发现。调用 ToolSearch 传 {"query":"RepoMap"}，ctx.searchTools 找到已注册、未激活且匹配的工具，更新激活集合并返回完整参数。下次重新生成清单就能公布定义。拿到接口后怎样用结构摘要找入口，见下一篇的代码定位示例。

src/ruocun/tools/registry.py · 第 129–146 行

直接点名未激活的工具且填参校验失败时，注册表提示先通过 ToolSearch 加载。如果模型已知道这个已注册的名字，参数又合法，注册表校验可以通过，后续仍按模式与权限决定能否执行。延迟激活控制公布清单，执行权限由运行时裁决。

05

同批执行的并行组与屏障

5.1 前两次读可以重叠，Edit 前后必须等

模型下一轮一次交来四项，顺序是 r_before 读价格、r_rules 读折扣、e_price 把价格从 100 改为 120、r_after 再读价格。假设它已经知道原文，写前基线仍然有效，四项都能成功。现在对照两种可能的调度，留意读取发生在哪个时刻。

如果两种调度都按原调用顺序回填，哪边仍会把 100 当成写后读数？

左边的 r_after 写入前已读完，返回 100。最后把它摆在 Edit 的结果之后也改不了已读到的内容。右边由写入屏障保证 r_after 在写入后才读到 120。

src/ruocun/tools/tool_batch.py · 第 343–364 行

代入四个调用，循环先把前两项加入 group。遇到 e_price，settle(group) 先等这一组，再用 settle([call]) 单独执行改价。循环随后把 r_after 放入新组，由末尾的 settle(group) 执行。改过的文件会继续存在，后读看到的内容随之改变，这类留在实际环境里的变化叫持久副作用。可并行的一组最多八项同跑，持久副作用或事后 Hook 会割开前后两组。这道屏障牺牲了一部分并行机会，换来写入前后各自可信的读数。

最后的回填顺序由调用 ID 保证，和执行时先看见哪个版本是两回事。若模型连 Edit 所需的原文都还不知道，就应该在第一轮只读，拿到回包之后再生成 Edit 参数。屏障只安排现有调用的执行时间。

「副作用屏障保护前后阶段的观察顺序。」配有持久日志时，副作用工具先登记意图，再进入处理器并保存结果。符合失败判断的 exec 可让后续 write、exec 跳过。若操作可能发生却缺结果确认，则会停止自动续跑，详见持久执行篇。

06

学习效果检测

6.1 判断参数校验、执行分组与回填

1． 校验回包指向 call-r。这次 Read 的参数是 {"path":"report.csv","offset":"2"}。同事准备去改文件权限。当前能定位哪一层失败？请写出还值得尝试的一次调用，以及怎样验证它确实读到了第 2 行。

展开详答

参数里的 "2" 是字符串，offset 要求整数，处理器还没打开文件。这条回包无法说明文件权限。用新的调用传 {"path":"report.csv","offset":2,"limit":1}，再看与新调用 ID 配对的工具结果是否返回第 2 行。

2．后一个 Read 先完成，能否把它的回包放在第一个？

展开详答

结果按 ID 找归属，最终按原调用顺序列出。组内完成时间可以不同，跨屏障的启动仍受约束。

3．第一个 Read 匹配事后 Hook，原来的并行组怎样变？

展开详答

它先等前组收尾后独占执行，Hook 也在这一阶段处理。第二个 Read 得等它收尾再进入后面的并行组。

模拟面试官提问

7.1 Agent 开发实习

独立核心题

怎样让模型传错参数后容易改对？

展开参考回答

口述回答。先用 schema 规定形状，失败时点名字段、说明原因并给最小示例。RuoCun 把这条反馈连同原调用 ID 一起交回模型，下一轮可改用 path。路径许可仍由程序检查。

可以分别交合法 JSON 的错字段、合法字段的未授权路径，核对两类错误在何处返回。

重点追问链

结构摘要工具只在少数任务里用，怎样减少每轮发送的定义？

展开主问回答

工具先注册为延迟能力，让 ToolSearch 按需公开完整定义，常规请求少背接口，第一次使用要额外发现。

追问 1 父代理在发出分叉请求之后才激活该工具，子任务会自动得到它吗？

展开追问 1 回答

回看分叉时固定的清单与双方的激活集合，在对应作用域决定是否需要发现。

追问 2 工具还没激活，但模型已知道名字，参数也填对了。执行器怎样判断？

展开追问 2 回答

当前注册表允许已注册工具以有效参数通过校验。延迟激活控制请求里的公布范围，模式和权限仍在实际派发时裁决。

7.2 Agent harness 岗位

独立核心题

为什么不把一批调用都丢进 gather？

展开参考回答

口述回答。写入前后的读取有观察顺序。RuoCun 等前面的无副作用组完成，独占执行写入，再启动后段。可以记录两个延迟 Read 和 Edit 的启动及返回时间，验证组内重叠与组间等待，同时核对调用 ID 和回包排列。

重点追问链

一批命令和写入里，前面的命令明确返回非零退出码，后面的 Edit 怎样处理？

展开主问回答

符合 looksFailed() 时记录失败，屏障可跳过后续写入或命令，先处理这个失败。

追问 1 如果命令可能执行了，但结果未能写入记录呢？

展开追问 1 回答

停止自动推进，查日志及原操作的副作用，贸然再发可能执行两次。

追问 2 如果只是回包完成顺序不同，怎样还原批次结果？

展开追问 2 回答

按调用 ID 收集，按原调用顺序回填。执行屏障约束何时开始，结果配对约束回到历史的每一项属于谁。

08

这一篇带走什么

RuoCun 按条件公布注册工具，模型提交调用后，程序检查参数与权限，再按副作用约束执行并回填结果。

  • 参数错误给出字段、原因和最小调用，并保留原调用 ID，让下一轮有依据修正。
  • 低频工具可以先登记、后公布完整定义，设计发现入口时要明确何时更新清单、执行仍有哪些检查。
  • 并行前先查状态归属及依赖，调用独用图片槽，写入用可等待的屏障保护前后观察顺序。
