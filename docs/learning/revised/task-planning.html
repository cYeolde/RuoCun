长任务怎样照着计划走？

两件商品，每件 100 元。预览页要把普通价算成 180 元，会员价仍是 200 元。两项结果现在就能写进计划。可搜索一下，示例目录和商店目录各有一份 prices.mjs，里面都有算价格的函数。到底该改哪一份？先看预览页实际用了谁。

价格可以先定，入口要去查

这次追到 shop/preview.mjs，发现它导入同目录的 prices.mjs。到这一步，才有证据把 shop/prices.mjs 写成修改目标。两项验收早就能定，具体改哪一份文件却得等这次读取。推演到验价时，先让普通顾客走一次预览页，得到 180 元。图里先填这一栏，会员价仍等下一次检查。

预览入口和回归命令如果一开始就确定，可以排好“定位、修改、验证”，再照着做。这是 Plan-and-Execute。开场遇到两份文件时，搜索只给出了候选，读取结果才决定下一步去哪里改，这一步就用 ReAct。同一次任务里可以两种都用。目标和验收条件先定，尚未查清的决定等证据。图里的下一步也很具体，普通价已经核实，换成会员身份沿同一个入口再跑一次。

交回一条待办，原清单只剩一条

把时间拨回刚找到入口、两项价格都还没验的时候。清单原来有三项，找入口、验普通价、验会员价。模型这次只把“找到预览入口，已完成”交回 TodoWrite，两项验价随即从清单上消失。留意下面给 ctx.todos 赋值的那一行。

src/ruocun/tools/todo_write.py · 第 17–29 行

todos 就是本次输入。函数先数有几项 in_progress，多于一项便拒绝，原清单还在。如果只收到一条完成项，计数为零，接下来就把这一条的副本存进 ctx.todos，两项验收随旧清单一起消失。「TodoWrite 的每次更新，都要带上更新后的完整清单。」这次应传入口已完成、普通价进行中、会员价待办。模型每次得多传尚未核实的事项，提交方也就能直接看出更新后还缺哪项。两项价格都跑过后再按各自证据更新。

把同一份待办交给 CoreCoder 本地源码的 todo_write。它把完成状态叫 done，校验后用 self._tasks = checked 整表替换，所以只交“入口已完成”也会丢两条验收。在两边都保存完整清单，后续才看得到还差哪项。 CoreCoder 待办工具

会员价验证还要跨轮跟踪，可以用 TaskCreate 把这件事单独登记。处理器把描述交给任务管理器，回给模型一个用于查询和结束该事项的编号。任务记录的初始状态是 running，意思是这件手工工作已进入跟踪。要开始测试，模型还得把实际命令交给 Bash，再留住执行器给的回执。

两个编号回答两件事。TaskCreate 给的编号能让人找到“验证会员价”这条记录。等 Bash 启动了测试，执行编号才能用来查这一趟的输出。一张任务单可以记着“还在查”，测试有没有开始得顺着第二个编号去看。 TaskCreate 处理器

同样把“验证会员价”写进任务单，在 Claude Code 已开启任务追踪的会话里，也要分开查待办和运行。Ctrl+T 展示工作清单，正在跑的 Shell 要到 /tasks 查。清单保留下一步要做什么，执行记录才告诉接手的人这趟测试有没有启动。 Claude Code 的待办与后台任务视图

反复搜索和等待测试

模型连发三次同样的 Grep，每次都只得到示例里的价格函数。缺口仍是“订单预览用哪个实现”。第四次可以直接 Read 预览页，沿导入路径核对候选。

若存也会在工具结果保存后看一眼这批动作。主循环把工具名、失败消息和当前是否有后台工作交给反馈处理。

src/ruocun/agent/loop.py · 第 463–467 行

单纯搜索几批，进度提醒的计数会累加。功能开启并达到门槛时，程序会把建议放进反馈，请模型挑一条尚无证据的假设来验证。启用相关反思时，程序还会观察重复错误和连续失败。程序看到的是动作类型和错误。一次 Edit 即可冲掉进度提醒的计数，但改到示例文件同样会冲掉。有没有帮到这笔订单，要看新结果解决了哪个未知。

反复查询有时是在等同一趟工作。假如价格测试已经确认在后台跑，几次 BashOutput 还没看到会员价输出，下一步要看这些查询跟的是哪趟运行。running_background 为真且整批都是查询工具时，若存将这批当作仍在跟踪后台工作，清掉进度提醒的计数。对模型而言，还要看查询是不是指向自己正在等的那次运行。只有手工清单时，应找真实的执行回执。有回执时，可以沿原编号等会员用例的结果。 对已存在后台工作的查询怎样计入进度

普通价通过，会员价还缺什么？

现在手里只有“普通顾客从预览入口得到 180”和“会员函数返回 200”。把第一条登记为已核实。下一步拿两件单价 100 元的商品，让会员走一次同样的预览入口，确认页面也显示 200。两个结果都写明用的身份和入口，接手的人才能复查。

三项都打勾，会员预览就算验过了吗？用例只交给 TodoWrite 三项 completed，就能收到“逐条检查实际证据”的提醒。这次更新只说明清单全绿，会员价仍得查实际运行。回到从用户入口核对价格的那一步，先确认这次检查实际走到了预览页。 完成项仍提示查证据的测试（项目回归测试）

普通价页面显示 180，会员价函数也返回 200，但是计划里写的是“验收两种价格的订单预览”。现在能把两项都打勾吗？

核对判断

普通价可以登记它对应的检查。会员价还要从订单预览的入口再查，才能证明用户会实际看到 200。

这一章带走什么

  • 计划可以先写明“预览里普通价 180 元，会员价 200 元”。仓库里有两份同名文件时，先查预览页导入哪一份，再把它写成修改目标。
  • TodoWrite 一次接收整张新清单。只交“入口已找到”，两项还没做的验价也会跟旧清单一起消失。

清单可以记下“验会员价”。要知道测试有没有启动，得找执行器给的运行编号。假如这趟测试还在后台，用户喊了停，手里的启动回执能说明它停了吗？
