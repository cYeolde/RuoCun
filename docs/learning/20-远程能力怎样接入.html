远程能力怎样接入

MCP发现、适配与不确定结果

资料检索和远程写入可以长成同一种工具。连接断开时，只有查清请求走到了哪一步，才能决定这次操作如何收尾。

01

写入回包丢了，重连以后能重发吗？

要查询另一个服务的数据，模型需要能用的工具。MCP 是让宿主发现并调用外部能力的协议。假设模型查到一条会员预览说明，接着要往资料系统追加核对备注。程序已经把调用交给传输层，等结果时连接断了。客户端手里只有本地的调用 ID c42。这个 ID 串起模型提议、本地意图及工具结果。它现在能证明什么？

首读自检 · 重连能区分甲乙吗？如果直接重发会怎样？

重连只能确认服务又能通信。甲可能完成一次写入，乙可能追加出第二条备注。先用 c42 核对本地意图与结果，再通过已授权的查询核验远端实际记录，留不出可信证据时保持未决。

上篇的 Skill给模型一套工作步骤，外部服务能实际返回查询结果或完成一次写入。RuoCun 用适配器把远端方法接入现有权限、执行记录和结果回流。适配器要把发送状态交给上层，才有机会区分明确失败和可能已经执行的写入。

02

连接、发现和本地 Tool 适配

2.1 初始化握手取得能力，再注册定义

服务可走本地子进程的标准输入输出，也可经 Streamable HTTP 或配置为 SSE 的客户端连接。传输建立后，initialize 将能力协商结果交给 manager。接入资料系统 docs 时，tools/list 找到 search_notes，注册成 mcp__docs__search_notes。前缀用来区分服务归属，处理时把原远端名称和参数交还协议。如果握手或构建定义失败，关闭这次连接，工具也不会从未完成的连接注册进来。

src/ruocun/mcp/mcp.py · 第 458–473 行

服务声明资源或提示词模板能力时，还可增加资源列表、按 URI 读取、模板列表、按名取模板等本地适配工具。列表是相应服务查询的结果。若服务通知能力变动，manager 重新取定义，按服务前缀替换注册项，并确认仍是同一个连接持有者，避免迟到刷新覆盖新连接的定义。

2.2 模型公布远端 schema，本地先验 JSON 对象

设 search_notes 公布必填字段 query 为字符串。本地为这项外部工具检查参数是不是 JSON 对象。先看这两份约定，再判断哪次调用根本到不了资料服务。

核对两个参数分别在哪里可能被拒

甲是数组，在本地对象校验被拒。乙是对象，能过这层形状校验。若另行通过权限且成功发给服务，服务仍可因缺少必填的 query 返回参数错误。

src/ruocun/mcp/mcp.py · 第 549–559 行

沿用内置工具的两个契约字段，apiParameters 是公布给模型的接口，schema 是本地校验的规则。MCP 适配把远端完整约定放进前者，本地保留对象这一最小条件。「公布的远端参数约定，与本地工具实际校验的范围要分别核对」。这样服务可以继续解释自己的完整约定，代价是有些字段错误要往返服务后才有反馈。资源地址与模板名称等包装参数另有局部校验，仍走本地权限与执行记录。

03

注册表与模型可见工具

3.1 ToolSearch 激活相关 MCP 定义

远端工具沿用注册与公布两步，另外维护一份 MCP 可见集合。假设资料服务接入了 7 项工具，初始注册中至多 5 项 MCP 工具会进入集合。检索项如果排在后面，可以经 ToolSearch 按名称或描述激活，后续请求才带上完整接口。计划模式生成清单时仍会排除 MCP。

src/ruocun/tools/registry.py · 第 84–100 行

激活只是改变本次能看见的接口，它仍需按真实参数和许可调用。注册定义会因服务连接更新而变化，移除定义会清掉相应可见项；续接时在实际可用的注册项中恢复有依据的名称。把定义和显露拆开能缩小模型每轮读到的工具面，也让这一阶段明确需要一次发现。

04

发送状态、远端结果与恢复

4.1 明确拒绝和结果不明走不同收尾

回到开场。如果明确在发送前停下，例如本轮在进入请求前已经取消，属于本地拒绝。如果收到经协议核对的错误回复，具体错误可以回给模型。像 c42 一样进入请求后因断线、超时或中途取消而缺少结果，程序保留结果不明。

src/ruocun/mcp/mcp.py · 第 524–547 行

一条明确的协议错误仍需按服务自己的约定判断业务效果。这里要对照两种 ID。SDK 的协议请求 ID 用来找这条外部请求的响应，前面的 c42 则按本地工具账本配对意图和回包。外部响应不明时，适配器把这个事实交回本地，让 c42 进入未决，避免模型因普通错误反馈而换个 ID 重写。

「重连恢复的是通信，未决操作要按原调用核对结果」。连接或发现可以重试，远端备注是否追加必须查实际记录，且再次执行需要明确决定。即使工具说明用 readOnlyHint 标成只读，也不能凭说明消除结果不明。继续追执行与结果记录可看 《工具可能已经执行》。

05

子代理专属 MCP 的连接归属

5.1 交接时重建连接并核对同一工具定义

子代理按角色准备资源时，可以打开指定的 MCP 服务。这里的 manager 是持有连接、管理其开关和工具定义的本地对象。每个独立执行管理自己的连接。前台任务移交后，接手者还要确认自己能以原来的接口继续。

src/ruocun/agent/agent_mcp.py · 第 63–72 行

归属移交时，先捕获原服务工具定义和可见名称，从接收方清掉原连接绑定的工具前缀，再用配置重建新的 manager。它打开后要求定义与原来的快照一致，再恢复可见集合。如果 append_note 的参数约定在中间换了，失败会关闭接续资源，避免把此前任务按新的接口直接执行。新连接一致只支持该项交接检查，旧的未决远端动作仍按原意图处理。

06

学习效果检测

6.1 分清接口校验、调用结果与连接状态

1．追踪接口 · 已注册但未显露的检索项，要如何让模型用真实 schema 调用？

展开详答

在允许 MCP 的模式下先通过 ToolSearch 匹配并激活，后续请求拿到完整定义，再交参数和权限流程。激活不会重新实现远端校验。

2． 同一次资料录入有两条调用。甲收到服务端明确的参数错误，乙请求发出后连接中断，没有响应。网络现已连上。哪条能据现有记录改参数，哪条还得核实远端？如果备注正文相同，应依据什么区分两次操作？

展开详答

对甲沿对应调用 ID 查看明确错误，按反馈修正字段。乙缺少远端执行结果，重连只恢复通信，先查原调用的本地意图和可对应本次操作的远端记录。相同正文分不出是谁写的，优先用服务提供的请求标记、审计记录等独立证据；仍无法区分就保留未决，避免重复追加。

模拟面试官提问

7.1 Agent 开发实习

独立核心题

接一个资料服务为什么只需要让工具管线认识 Tool？

展开参考回答

“MCP 层负责连接、发现和协议调用，再把每项能力转成统一工具，用命名空间区分服务。模型和执行管线沿用原来的定义、权限、意图和反馈流程。”

重点追问链

模型看到接口却传错了字段，哪里给反馈？

展开主问回答

“先看错的是外层形状，还是服务约定的字段。两层拿到的 schema 不同。”

追问 1 给数组会怎样？

展开追问 1 回答

本地对象验证失败。

追问 2 给了对象却少远端 query 呢？

展开追问 2 回答

本地这层不检查该字段，远端按自己的约定处理。

追问 3 资源 URI 没给呢？

展开追问 3 回答

资源适配自己的本地 schema 有必填规则。

7.2 Agent harness 岗位

独立核心题

如何防止恢复连接时重复写？

展开参考回答

“本地把原操作按调用 ID 记录意图，协议层告诉我请求明确未发、得到明确回复，还是可能执行却未确认。最后一种保留未决，只恢复通信，重新执行须另作裁决。”

重点追问链

子任务切换 owner，原连接怎么交接？

展开主问回答

“用原配置和执行上下文新建连接，核对接口快照，再恢复对应的显露集合。”

追问 1 为什么不复用旧连接的 handler？

展开追问 1 回答

它已捕获旧连接和归属，结束时由旧 owner 管理。

追问 2 新连接定义变化呢？

展开追问 2 回答

接续失败并关闭新资源。

追问 3 定义一致能继续未决的远端写吗？

展开追问 3 回答

仍需原调用的确认和明确恢复决定。

08

这一篇带走什么

MCP 将协商、发现和调用外部服务的过程适配成普通工具，再通过独立的可见集合、权限、结果确认和连接归属管理整次执行。

  • 接入外部服务时单独追模型拿到的参数定义、本地确实检查的规则和服务端责任。
  • 接口多时分开管理注册与显露。激活和重新绑定之后，用实际工具清单检查模型能看到的定义。
  • 写请求可能已执行却未确认时，按原调用保留意图并查外部状态。先恢复连接可以通信，确认结果还有自己的证据链。
