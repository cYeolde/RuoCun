摘要丢了细节怎样回查

原文身份、来源与分页

从一句含糊的摘要追到两次“检查通过”，用原文来源确定哪条能支持会员折扣。

01

同一句“检查通过”，能证明会员用例跑过吗？

沿用上篇确认保存的新摘要和归档 ID。摘要“会员日志已保留，检查通过”附有 [原文归档:summary-demo-2]，但当前要回答的是：会员过期时是否按普通价计算？旧历史里有两条正文相同的结果，一条来自冒烟检查，也就是先验证基本功能可运行，另一条来自会员专项用例。若归档只按正文合并两条“检查通过”，留下的调用可能恰好无法回答这次问题。

源码推演 · 找到应与会员调用配对的回执
原文位次调用回执正文回执配对 ID
先保存冒烟检查检查通过r-smoke
后保存会员用例检查通过r-member
首读自检 · 两条回执都写通过，你会找哪一条，还要核对什么？

找 r-member。还需要找到对应的调用参数或实际检查内容，确认覆盖“过期会员”。用相同文字合并两条回执会破坏这种核证能力。

02

原文身份、版本与当前投影

2.1 两条正文相同的消息分别占一个原文序号

新投影只带了压缩后的材料，归档仍保留已接纳并脱敏的历史消息、必要的协议字段及附件引用。这里有三种编号：tool_call_id 找到原来的调用，raw_seq 找到原始消息在本会话、执行范围内的位置，summary-demo-2 则是查这份派生记录的入口。一条消息首次进入存储时，raw_seq 按该执行范围的追加顺序增长，初始版本为 1。r-smoke 和 r-member 的回包各占一个位置。

src/ruocun/session/archive.py · 第 145–164 行

已有位置再次保存相同消息时复用原引用。若现有原文只更新受控元数据，例如图片投递标记，就在同一 raw_seq 写下一版本，并记录 previous。所以台账中会同时出现“不同原文”和“同一原文的新版本”。把上一节两条回执设成 4 和 8。如果序号 8 从 v1 变成 v2，回查仍应有 4、8 两个位置。哈希核对各条记录内容，内容的相似与否不决定归属。

「历史证据按原文身份去重，正文相同仍可来自不同操作」。将来用证据核对一趟运行时，也能沿保留的配对 ID 找回操作缘由。

2.2 摘要与裁剪保存原文来源

第 14 篇的提交校验已经保证了摘要和引用一起发布。那条引用为什么能帮助回查，还要看 sources。摘要是由旧消息生成的派生记录。程序用它实际读入的旧消息位置，查到原文或更早的派生记录 ID，再把这些 ID 存为来源。摘要文字怎样措辞都不会改变这份来源清单。

src/ruocun/session/archive.py · 第 253–267 行

示例的 summary-demo-2 来自第二次压缩。假设原始会话有系统约定 raw_seq=1，冒烟和会员回执分别为序号 4、8。第一次摘要后，系统约定仍在当前投影，第二次摘要会再读一次它。顺着两条来源路线数，应该返回几条原文？

数到四次访问，但只对应三条原文。只查直接来源会漏掉序号 4 和 8，沿路直接拼文本又会重复序号 1。代码递归展开所有路线，以原会话、原执行范围和原文序号组成键，保留每个键可达的最高版本。这样序号 4 与 8 虽然都写“检查通过”，仍会各保留一条。沿所有路线能到达的完整集合叫来源闭包。

src/ruocun/session/archive.py · 第 350–368 行

存来源关系可以避免每次摘要都复制旧正文，读回时要多做展开、版本合并和校验工作。遇到循环或引用缺失会停止，避免把半段材料交给模型当完整证据。

2.3 回退改投影，分支复制可达来源

清空、回退会改变当前历史投影，并登记操作边界供复盘。原来已保存的证据仍属于原会话。新建分支时，只从选中的投影引用出发，复制能到达的原文、派生记录、先前版本及必要附件引用。这样即便后来删除源会话，分支能回查自己带入的材料。已从来源投影移除、且没有任何保留引用能到达的片段不会跟过去。旧运行的权限和副作用也不会因数段文字被复制而重新生效。

03

ArchiveRead 的执行范围与分页

3.1 调用只传归档 ID，范围由执行器绑定

从新摘要末尾的 [原文归档:…] 拿到 ID 后，ArchiveRead 接收必填字符串 id、可选的非负整数 offset 和取值 1–16,000 的整数 limit。省略时分别从 0 开始、读 4,096 个字符。工具验证 ID 的字符形式和取消状态，再向 ctx.archiveRead 请求一页。存储层仍会在绑定会话的当前执行范围按合法身份查询。接口没有可由模型设置的会话或范围参数。

src/ruocun/tools/archive_read.py · 第 14–26 行

主会话绑定其存储的 main 范围。子代理先清除从父上下文复制来的读取回调，再用自己的入口绑定当前 run。第 13 篇的Fork只能带入实际继承的历史及能沿来源找到的归档。其他执行中的 ID 即使格式正确，在当前入口也找不到那条记录。「归档 ID 负责定位，读取入口决定它在哪个范围有效」。旧日志里有文件名、链接或命令时，读回文字不会替当前工具授权。

3.2 沿 next_offset 读完需要的证据

回查派生 ID 后，text 是来源展开后的 JSON 文本切片，偏移按字符计算。先读第 1 页，看 text 停在哪，以及下次请求应填哪个 offset。示意原文只摆两条工具回包，真正核证时还应查同组调用。

04

学习效果检测

4.1 判断归档身份、授权与分页结果

1．同一回复文字被两次保存为不同原文。其中第二条更新了图片投递标记。展开摘要应保留几条？

展开详答

两条。第二条的元数据变化在同一原文序号上增加版本。展开时在可达记录中取该序号的最高版本，保留第一次真实产生的原文。

2．原范围有摘要 S1，后来 S2 同时引用 S1 和 S1 已使用过的某条原文。为什么不会重复展示那条原文？

展开详答

展开递归跟随派生来源，到叶子时按原会话、原范围、原文序号合并，再按序号排列。重复路径与真正的两次历史发生有不同身份。

3．子代理拿到了父会话的合法归档 ID，为什么还是读不到？

展开详答

工具只收 ID，具体查询范围来自子执行自己的已绑定读入口。只有被真实继承并复制进该范围的来源可以找到，获知 ID 本身不扩大范围。

4． 同一页里看到了 r-smoke，另一条“检查通过”刚露出开头。当前回包给 id=report-2、next_offset=96，你要核实会员专项。第一条通过能交差吗？写出下一次请求，再指出拿到第二条回包后还要核对哪条调用。

展开详答

只能确认第一页出现了冒烟检查的回执。用相同范围继续发 ArchiveRead({"id":"report-2","offset":96})，按后续回包给的偏移查完所需证据。找到专项回执后，用它自己的调用 ID 查到原命令和断言范围，再决定是否覆盖会员专项。

05

模拟面试官提问

5.1 Agent 开发实习

独立核心题

摘要写“测试通过”，还要如何核实才可以交付？

展开参考回答

我会定位该摘要的归档引用，按需回查对应的调用和回包，确认测试名称、实际输入和结果覆盖用户要求。若结果缺了条件，继续补能够验证该条件的证据。

摘要适合续接方向，归档适合核对原始依据。版本和来源身份帮助定位正确的一趟执行。

重点追问链

怎样把归档页用在真实任务里？

展开主问回答

我先看当前目标缺的是哪条可核实信息，再从摘要或裁剪标记取 ID，逐页读取。

追问 1 一页中有两个“通过”时怎样选？

展开追问 1 回答

进一步检查工具配对 ID 和调用参数，找到验证了目标条件的一趟。

追问 2 读到一半已明确要查的记录时怎么办？

展开追问 2 回答

如果证据够用就停止回查。如果需要机器解析整个 JSON，则沿偏移拼齐，再验证消息关系。

5.2 Agent harness 岗位

独立核心题

怎样让多轮压缩后的摘要仍可审计？

展开参考回答

我会给原始消息稳定身份，派生摘要和裁剪记录保留对实际来源的引用。在一次提交中登记新投影和这些来源。读取时递归展开，按原文身份合并可达版本并恢复原序。

按正文哈希去重会丢掉真正的重复动作。哈希适合校验记录完整性，来源身份能说明它来自哪一次。

重点追问链

会话分支和子代理如何读取继承历史？

展开主问回答

分支复制当前投影能到达的来源闭包，读取入口绑定到该执行自己的会话与范围。

追问 1 源会话删除后会怎样？

展开追问 1 回答

已经复制的闭包和附件仍为分支保存可回查的材料。

追问 2 如果目标范围的记录包含原父任务的一条写入指令呢？

展开追问 2 回答

只把它作为过去的证据，当前是否能执行依然走当前授权和工具派发。

06

这一篇带走什么

模型在短投影上继续工作，需要历史细节时再沿提交过的派生来源，在当前范围内分页查回原文。

  • 为真实消息分配原文序号和版本，用原会话、范围与原文序号判断身份。重复文字和元数据更新分别处理。
  • 派生记录保留真实来源，并随检查点一起提交。分支想独立回查，就复制实际可达的来源闭包。
  • 读取入口绑定执行范围，归档 ID 只做定位。对长证据按页消费，返回的偏移和原文配对信息足够继续核对。

归档按原文身份追到历史证据。下一篇看另一件事：即使没查任何归档，同样的 system、工具定义和历史出现在两次实际外发请求的开头，模型服务也有机会复用此前的计算。
