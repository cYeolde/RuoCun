Glob、Grep、Read怎样配合

手里只有一句“文件自上次 Read 后已被外部改动”。顺着这条反馈找到抛出错误的地方，再追到真正使用这项检查的代码。

01

只知道报错，第一步搜文件名还是搜内容？

价格文件已经 Read 过，但提交 Edit 时被拒绝。上一章用填错字段的反馈定位了失败的关口。这次参数有效，失败来自处理器。现在手里只有一句报错，连条件写在哪个文件都不清楚。把那句话交给 Glob 匹配文件名，结果为空。改用 Grep，从工具目录搜报错文本，得到第一条可用线索。

实际应把什么传给 Read？为什么要从第 108 行之前开始读？

给回包中相对于 Grep 搜索根的 paths.py 补上 src/ruocun/tools/，传给从仓库根读取的 Read。第 108 行只告诉你拒绝发生在哪，从第 100 行读才能看清 checkReadBaseline 的入口和拒绝条件。再沿这个函数名找谁在写前调用它。

这次查询的目标是找到一次真实的拒绝是怎样发生的。目录和文件名先给候选，内容命中给位置，原文和调用点才能解释程序为什么拒绝。第二篇算过 Read 从当前工具目录找文件，Grep 又有自己的搜索根。两段路径都相对时，「让下游读到同一文件，要带上上游结果的解释起点。」

02

路径候选与遍历范围

2.1 Glob 在搜索根下匹配相对路径

假设只知道文件名大概包含 edit，这时才轮到 Glob。传 {"path":"src/ruocun","glob":"**/*edit*.py"}，**/ 允许前面有零层或多层目录，* 匹配一段不含斜杠的字符，? 匹配一个非斜杠字符。tools/edit_file.py 是这个模式的候选之一，返回地址以这次给定的搜索根为基准。下一次把路径交给 Read 时，要按会话目录补齐搜索根。

src/ruocun/tools/glob.py · 第 14–28 行

Glob 的接口有两项。glob 是必填的模式字符串，path 是可选的搜索起点字符串，缺省传 . 交给路径授权与解析。遍历可能跳过固定忽略目录、目录链接和无法访问的条目，最多拿前 50000 个文件来匹配，再按修改时间降序返回前 100 项。刚改过的文件更容易出现在列表开头，但这张列表回答的是候选范围。

src/ruocun/tools/glob_files.py · 第 25–37 行

「空结果只对这次实际搜索过的范围负责。」例如缩错 path、写错层级模式，或者目标落在遍历上限之后，都会使目标不在结果中。结合参数和搜索边界调整范围，再决定是否需要换成内容或符号查找。

内容命中与结果范围

3.1 Grep 用 Python 正则，每种模式返回不同粒度

从仓库根出发，传 {"path":"src/ruocun/tools","pattern":"文件自上次 Read 后已被外部改动","type":"py"}。这个模式没有正则元字符，可以直接匹配报错正文。默认 mode="content"，回包中的这一条形如 paths.py:108: …。换成 mode="files" 则返回 paths.py，路径相对于搜索根。用 context:2 看命中周边时，会带出前后各两行，但仍需看更上面的函数入口和调用点。

src/ruocun/tools/grep_files.py · 第 143–168 行

Glob 的模式对路径生效。Grep 的 glob 只匹配文件名末段，type 按已知扩展名过滤。比如要扫工具目录里的 Python 文件，设 path="src/ruocun/tools" 配 glob="*.py" 就够。若改为 glob="tools/*.py"，带斜杠的模式对这里的末段文件名不会命中。下面这个条件就解释了为什么。

src/ruocun/tools/grep_files.py · 第 105–120 行

3.2 先缩小搜索，再读上下文、分页或匹配片段

默认输出一整行的缩略文本，长行只展示前 300 个 UTF-16 代码单元。报错恰好在行尾时，可以用 only_matching=true 加 match_context=12，让输出对准命中的片段，给出行、列和命中附近的字符。只有 mode="content" 才能看这种结果。普通上下文模式的 head_limit 按输出行来判断何时停下，最后一组前后文可能越过阈值。offset 跳过的是正则命中项，两者不能当作同一种计数。整个结果还有长度上限，到达上限后可缩小搜索目录或收紧正则。

参数类型及默认影响
pattern必填字符串Python 正则。按原文查找普通符号时需转义，例如给 ( 加反斜杠。
path / glob / type可选字符串，缺省从 . 开始，另两项不限制搜索目录或指定文件，按末级文件名模式筛选，或按已知文件类型筛选。未识别的类型不会产生扩展名限制。
mode可选枚举，默认 contentcontent 报到行，files 只列路径。
ignore_case / multiline可选布尔，默认 false是否忽略大小写，是否按整个文件匹配并允许点号越过换行。
before / after / context可选整数，均非负，默认 0前后文行数，每侧取单边值与 context 的较大值。
head_limit / offset可选整数，前者至少 1，默认 200，后者非负，默认 0前者达到输出行数阈值后停止搜索，带上下文时会先添加整组。后者跳过命中项。文件模式中以命中文件为单位。
only_matching / match_context可选，前者布尔默认 false，后者整数 0–200，默认 0将匹配文本标为 <<…>>。第二项只在片段模式下生效，按 UTF-16 代码单元保留周边字符。

填 3 会跳过全部已知命中。上次只查到一处匹配，所以填 1 才能从第 10 行续搜。

代码先在 hits() 循环内增加 total，再为本次命中追加前后文，最后看 len(out) 是否达到阈值。一处命中可以占三行展示，所以即使没有命中第 10 行，首份回包仍已有三行。上下文让模型更快判断命中是否相关，也让展示行数失去作分页游标的资格。看到截断，优先缩小范围再搜。看到空结果，核对路径、文件类型、正则和跳过数。

原文、读取基线与调用点

4.1 Read 从搜索行号向上找定义

在仓库根调用 Read：{"path":"src/ruocun/tools/paths.py","offset":100,"limit":9}。这里的 offset 是起始行号，从 1 开始，limit 是显示的行数。下面直接看这九行源码。读取记录按绝对路径拿出旧 meta，再取磁盘上的当前时间和大小。只有两份元数据不一致才进入外部改动这条拒绝分支。

src/ruocun/tools/paths.py · 第 100–108 行

现在用 {"path":"src/ruocun/tools","pattern":"checkReadBaseline","mode":"files"} 找定义、导入和调用的候选文件。再读 edit_file.py 的第 78 行与 write_file.py 的第 41 行，确认两者都会调用它。文件清单只指示还该读哪里，读到调用表达式才确认这个函数真的参与写前控制。

src/ruocun/tools/edit_file.py · 第 75–82 行

Read 默认显示 2000 行。每行超过 2000 个 UTF-16 代码单元时会截成预览。超过 5 MiB 的文本应显式传分页参数，目前实现仍整份读取字节再切行，缩小的是回包。Grep 只提供找到文件的证据。文本 Read 还把开始读取前的修改时间和字节数留给程序，写入前据此发现文件可能已变化。这份供比较的读取记录称为基线。若成功访问还可能触发附近 Skill 的发现。基线何时会挡住修改，留到文件编辑篇的外部改动示例代入。

06

结构摘要与语义导航

6.1 RepoMap 缩小入口，LSP 沿符号定位

如果线索是“文件编辑的模块在哪里”，可以先读 RepoMap。它在 cwd 或工作区根索引支持语言的函数、类和其他定义，再按 max_tokens 限定的 token 预算挑符号展示。扫描到上限时，回包会提示覆盖范围。先用摘要选目录，再找完整定义。

src/ruocun/tools/repo_map.py · 第 10–20 行

平时，文件大小和修改时间都相同就复用提取结果。假设同步工具替换了一段同样长的函数名，还保留了原修改时间，此时缓存可能列出旧签名。给 RepoMap 传入 {"refresh":true}，本次会跳过文件提取缓存，在原有扫描范围内重新解析。后续调用可以复用这次提取的新结果。

具体到 checkReadBaseline，Grep 匹配同名文字，遇到两个模块各有一个同名函数还要继续判断。编辑器里“跳到定义”常通过 LSP（语言服务器协议）请求一个理解源码的程序，让它按光标位置找到实际引用的定义。RuoCun 的调用同样可以在实际调用位置传文件、行、列，用 goToDefinition 追定义，或在定义位置用 findReferences 找引用。workspaceSymbol 需要 query，filePath 供选择服务器，documentSymbol 列文件内符号而无需行列。服务不可用时，回到文本搜索和源码阅读。语义结果也需要用 Read 查看上下文，才能判断调用在哪个分支发生。

08

模拟面试官提问

8.1 Agent 开发实习

独立核心题

只给一条报错，怎样找到该看的实现？

展开参考回答

口述回答。我先用 Grep 搜内容，把命中当成定位线索，再 Read 报错之前的函数和条件，最后搜函数引用并核对实际调用分支。RuoCun 这条外部改动错误出现在 checkReadBaseline()，Edit 和 Write 都会用到这项检查。

重点追问链

知道完整报错，在预计的目录搜却没结果，你从哪里查起？

展开主问回答

检查正则、相对目录、Glob 匹配对象、文件类型和跳过数量，随后有针对性地放宽条件。

追问 1 放宽目录后一口气返回大量结果，其中还截断了。怎样重新定位？

展开追问 1 回答

用较小路径范围或更特异的符号缩小查询。要看长行尾部就用匹配片段，要理解控制流就读原文件。

追问 2 同一段报错出现在测试和工具实现两个文件，怎么找实际入口？

展开追问 2 回答

先读出各自所在函数和条件，再沿生产调用位置追到实际派发路径。测试能展示一种输入会发生什么，调用点能解释这个分支在何时介入。

8.2 Agent harness 岗位

独立核心题

为什么区分搜索预览和真正读文件？

展开参考回答

口述回答。搜索为模型挑候选并控制回包大小，Read 让模型看到所需上下文，还会建立写前校验需要的元数据。用临时文本文件验证，可分别比对 Grep 后和 Read 后的已读状态，以及外部修改后 Edit 的拒绝结果。

重点追问链

给 Grep 加前后文后为什么不能按显示行数翻页？

展开主问回答

上下文产生多行输出，offset 却数命中项。先确定接口的分页单位。

追问 1 下一页找到了正确的文件和行号，Read 为什么仍可能选错文件？

展开追问 1 回答

结果路径相对搜索根，Read 相对执行上下文。明确保存搜索根，转换后再读。

追问 2 若没有可用的语言服务器，怎样确认这个文件里的函数被调用？

展开追问 2 回答

用 Grep 找符号的定义、导入和引用，再用 Read 核对调用表达式及所在分支。命中列表只负责缩小阅读范围。

09

这一篇带走什么

代码定位从已有线索选择搜索入口，用命中缩小范围，再读出条件和调用关系，确认真正负责行为的实现。

  • 路径模式与内容正则对应不同对象。跨调用传递相对路径时，把它的搜索根交代清楚。
  • 遇到空结果或截断，先查扫描范围、过滤器和计数单位，再决定重搜或分页。
  • 命中只定位值得看的位置。准备改文件时用 Read 核对上下文并建立基线，用实际调用点或语义引用验证责任。
