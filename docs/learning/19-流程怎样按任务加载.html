流程怎样按任务加载

Skill目录、正文与动态发现

查会员预览错误时，先用启动目录里的调试流程。读进模块后，RuoCun 才发现该目录自己的测试流程。两份流程各在什么时候对模型可见？

01

Read 已经找到文件，为什么同批 Skill 还读不到测试流程？

在工作区根启动，模型看到简短的 debug 描述。它想先打开 packages/pricing/preview.py，再取附近的 pricing-tests 正文。后者位于 packages/pricing/.ruocun/skills/pricing-tests/SKILL.md，尚未加载到启动清单。设模型在同一份响应里提出了两个工具调用。

首读自检 · 同批 Skill 看得到正文吗？下一轮怎么填？

同批 Skill 只查当时的活跃清单，找不到 pricing-tests。等下一次请求看见新增目录，模型才有依据提交 {"name":"pricing-tests"}，这时工具查到的清单与模型看到的目录对应。

模型输入篇已经展示了首条 system 可以带一份 Skill 目录。这里跟踪两次交付，先让模型知道有这种流程、什么问题适合用它，再在需要时把完整步骤送进任务。第 4 篇的 ToolSearch 把工具参数接口加入可见清单，此处的 Skill 则取得一份供模型读的流程正文。

02

启动目录、覆盖与调用入口

2.1 原生项目条目参与同名覆盖

加载器从磁盘读取 SKILL.md。顶部两行 --- 之间是 YAML 配置，也叫 frontmatter，记录名称、用途和触发条件。其下的 Markdown 是模型按需获取的步骤。启动时目录来源依次为已配置兼容用户、原生用户、已配置兼容项目、原生项目，加载器先以实际文件路径去重，再按名称让后面的项覆盖前面的同名项。磁盘同名项也会遮住内置 core 项，停用项被过滤。--no-skills 会跳过启动 Skill，关闭磁盘发现。

src/ruocun/skills/skills.py · 第 131–145 行

若根部有一个 debug，带 paths 的 pricing-check 则属于触发有条件的项。paths 用路径模式说明哪些文件与该流程相关。启动扫描能命中路径时直接使它可见，扫描上限为 4000 个文件。动态发现启用时，未命中的条件项可先放入待匹配池。目录公布名称、条件和短描述，完整正文按需领取。

2.2 模型调用与用户命令有独立过滤规则

src/ruocun/skills/skills.py · 第 15–24 行

src/ruocun/skills/skills.py · 第 27–37 行

src/ruocun/tools/skill.py · 第 23–28 行

src/ruocun/agent/runtime.py · 第 1250–1252 行

假如已经加载的 pricing-tests 设置了 disable-model-invocation: true，/skills 面板会将它标为“仅手动”。模型目录会略去它，Skill 工具也会在匹配名称前过滤它。模型即使知道调用名，也不能通过这个工具取到正文，查找失败时列出的候选同样省去这一项。用户的斜杠入口按 user-invocable 判断。只要该项仍在活跃清单里，且没有设为 user-invocable: false，用户输入 /pricing-tests 就可以展开正文。入队时同时保存原命令和这次展开结果，恢复时使用当时确认的正文。

03

正文返回与执行权限

3.1 Skill 结果带正文、资源根和任务参数

模型用必填字符串 name 选择目录里的条目，若要给流程补充任务参数，可再传字符串 args。处理器优先找带命名空间的调用名，例如 reports:audit，再尝试实际名称和简名。命中后更新使用次数和最近调用日期。目录和动态发现仍按上文的覆盖、启停和路径规则处理。工具按需适配正文，附带资源根、用户参数和执行约定。相对资源以该 Skill 所在目录为根，后续还需实际读取。

src/ruocun/tools/skill.py · 第 30–44 行

「流程正文可以安排工作，真正能执行什么由工具和权限决定」。正文中列出 Read、Bash 或 Edit 时，模型仍需独立发起调用，再经过本次操作的权限裁决。下面拿一条实际模型回包核对这种分工。

04

文件访问、候选准备与确认

4.1 成功访问的路径驱动就近扫描

Read 先通过路径授权，再读文件。在本例的成功文本读取路径上，它把解析后的实际路径报给访问回调。只在请求里提到文件名，没有通过访问边界，发现器就缺少这条输入。对真正访问过的 packages/pricing/preview.py，发现器从父目录向上找子树的原生 .ruocun/skills，根目录的目录已由启动加载负责。候选目录的物理目标必须位于工作区内。发现器避开已确认扫描的目录，并过滤停用、已有名称和已知文件。

src/ruocun/skills/discover.py · 第 70–91 行

同一经过验证的相对路径也会与待匹配池的 paths 模式对照。这里可能同时得到两类信息：例如规则早已读到内存，此次路径命中才激活的 pricing-check，以及刚从子目录读出的 pricing-tests。前者来自路径条件，后者来自此前没有读取的目录。动态扫描失败时，原来已经在池里的路径条件仍可进行匹配。

4.2 先提交目录消息，再确认候选状态

准备阶段用清单、停用状态和已查目录的快照，返回候选和目录文字。压缩篇也用过先保存后切换的顺序。这里要先保存模型会看到的目录消息，再更新内存里的活跃清单和已扫目录。让开场保存目录这一步失败，看看两种顺序会留下什么。

核对哪一列会使模型看到的目录与工具查阅状态脱节

立即登记时，本轮的清单已经变了，会话里却没有对应目录。再次访问同一模块时，还可能因已扫标记跳过，错失重新公告。先保存后登记要多保留一份待确认候选，换来两份信息能一起推进。

src/ruocun/agent/runtime.py · 第 1983–1990 行

replace_context 把目录作为追加的 system 消息保存。返回后 confirm 才记已扫目录、移出已匹配条件项、更新活跃 Skill。没有可公布条目的候选可在同一边界直接确认，无需追加空消息。「先保存模型能看到的目录，再推进已确认扫描和激活状态」。保存前会检查取消和代次，成功提交途中收到暂停也会完成同一候选的确认。

05

学习效果检测

5.1 判断目录发现和正文的生效时机

1． 模型在目录里看见 invoice-check，随后成功取到正文。正文要求先读 Skill 目录下的 fields.json，再核对工作区的 invoice.csv。到此能报告“字段正确”吗？下一步两次读取分别以哪里为起点？

展开详答

当前能确认流程可用及它要求的步骤。先根据 Skill 回包给的资源根定位 fields.json，再按当前执行目录和任务路径读取实际的 invoice.csv。分别取得两份配对的工具结果，比较字段后才能报告。目录和正文都没给出这份发票的实际表头。

2．预测状态 · 候选扫描完成，但保存目录消息失败，已查目录应不应该增加？

展开详答

不应提前增加。prepare 只生成候选，保存异常时走不到 confirm。修复保存问题后，后续符合条件的访问仍可准备候选。

06

模拟面试官提问

6.1 Agent 开发实习

独立核心题

怎样让 Agent 按需加载一套测试流程？

展开参考回答

“短目录回答何时用哪套流程。模型找到相关项后调用 Skill，正文和资源目录随工具结果返回。下一步用真实工具逐项执行。”这样启动输入不用装下所有正文，代价是遇到适用任务要做一次查阅。

重点追问链

有流程写了测试命令，模型怎样真正运行它？

展开主问回答

“先确认这份流程适合当前任务，再按资源位置读材料，最后用可用工具执行。”

追问 1 流程给的相对路径从哪算？

展开追问 1 回答

引用材料以 Skill 目录为根，实际调用仍须明确路径。

追问 2 如果需要改文件，正文能授权吗？

展开追问 2 回答

调用由正常模式与权限裁决处理。

追问 3 正文测试用的是旧入口怎么办？

展开追问 3 回答

先核今日调用路径，再修正测试输入。

6.2 Agent harness 岗位

独立核心题

动态发现为什么要把准备和确认拆开？

展开参考回答

“发现器先找候选和目录文本，避免提前改变当前清单。会话保存目录后才提交已扫目录和激活状态，让下一轮模型能查到它刚看到的项。”验证时看会话追加消息、扫描记录与实际查阅结果三者。

重点追问链

在保存附近遇到失败或暂停怎样处理？

展开主问回答

“先以会话提交边界判断公开是否发生，再推进同批候选。”

追问 1 提交前收到取消呢？

展开追问 1 回答

跳过发布，不确认候选。

追问 2 消息保存后才暂停呢？

展开追问 2 回答

完成同一候选的确认。

追问 3 发现了一个 model 隐藏但用户可用的项呢？

展开追问 3 回答

没有模型目录文本可以保存，候选的活跃状态仍可确认。目录显露不能用作权限隔离。

07

这一篇带走什么

RuoCun 先用目录显露流程入口，按需把正文交给模型，并在文件访问后的安全边界扩充本会话已确认的清单。

  • 流程集合很大时先发用途和调用名，选中后再给步骤及资源位置，减少每轮都背全部正文的开销。
  • 同时维护模型可见目录和运行清单时，先确认目录消息，再登记扫描与激活，提交失败时保留再次发现的机会。
  • 脚本步骤、能力注册和执行权限各自有来源。加载正文后，实际动作仍要有可用工具和独立授权。

CSV 实录里的实际动作是本地 Read。如果下一步需要查外部资料库，就要先把服务能力接成一个工具。下一篇追到外部请求的明确结果和未决状态。
