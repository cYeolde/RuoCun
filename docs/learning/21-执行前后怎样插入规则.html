执行前后怎样插入规则

Hooks改参、决策与收据

在写入前检查目标，在写入后登记结果。只要钩子自己也能产生副作用，执行顺序和恢复记录就值得单独设计。

01

Pre Hook 换了参数，哪份才该拿去校验和批准？

模型准备写一份会员预览核对笔记。项目约定把报告放到 reports，于是写入前触发了 PreToolUse。Write 需要 path 和 content 两项。看 Hook 的两种输出，先判断它们各能走到哪一步。

首读自检 · 哪一项会问用户？问题里应出现哪个路径？

甲少了 content，在参数校验处停下。乙满足这两项字段要求，若权限层允许询问，则应询问实际要写的 reports/preview.md。原调用 ID 仍是 w7。

前篇的 MCP让模型可以调用外部能力。Hook 是程序在指定事件发生时运行的配置命令。模型提出 Write 后，程序就在执行前决定要运行哪些命令。要跟踪它的效果，先看它取得哪份输入，又能向执行器交回什么。

02

事件匹配、输入与结构化结果

2.1 按时点选择命令，按结果种类消费回包

事件输入或时点这一处怎样消费结果
PreToolUse工具名称和原始参数可改参数、阻止本次调用或提出权限意见，也可提供上下文。
PostToolUse工具、最终参数和已保存结果执行后置规则并保存独立收据。当前批执行器继续使用已确认的原工具结果。
UserPromptSubmit准备消费的用户输入可阻止提交，允许时附加上下文与输入一同保存。
SessionStart / SessionEnd会话启动、恢复或收尾启动可附加一条 system 消息，结束用于收尾动作。
SubagentStart / SubagentStop子运行身份与类型开始事件执行后，额外上下文需保存确认，才能发子代理模型请求。结束事件也用独立的 Hook 收据。

选择命令时先对事件，匹配器通常检查工具名，SessionStart 用启动或恢复来源。工具事件的 if 还可看参数条件。运行器执行匹配的 command 项，将本事件载荷作为 JSON 写入标准输入。命令默认 30 秒超时，设置 timeout: 0 关闭该时限，输出受 4 MiB 上限保护。超时或输出超限的结果不作为权限决定或改参继续消费。

退出码 2 会形成 block 和原因，Pre 的消费点把它当 deny。成功输出的普通文本可作为附加上下文。结构化结果可以含 hookSpecificOutput.permissionDecision、updatedInput 与 additionalContext。多个 Hook 匹配时合并上下文，决定取 deny、ask、allow 中较强的一个，最后一个提供的完整 updatedInput 生效。输出字段能否改变流程仍取决于事件消费点。

04

工具确认、Post 时点与收据

4.1 保存原工具结果后才执行 Post

从原工具的意图与结果接着往后看。原处理器返回并确认保存的结果是 Post 的输入，另外还要匹配条件且未取消。这里“正常返回”只说明处理器交回了工具输出，字符串里仍可能报告业务失败。Post 触发时要读原工具结果，才能决定怎样收尾。

第一列先查 Write 的实际文件，因为程序未拿到确认；按照当前顺序，Post 还没有启动。第二列保留已经确认的 Write，核对 Post 有没有把记录加到日志，不能为追这个回包再写一次文件。

4.2 Hook 收据绑定事件、调用和已选命令

Hook 记录使用事件与原身份生成独立 ID，并把最终参数或载荷、工作目录、选中命令的摘要纳入意图。可以取用可信已确认结果时，根据收据摘要核对并恢复结构化结果。执行记录允许继续且没有可复用回包时才实际运行命令。已有意图却无法确认效果，或回包不可信，处理为 HookOutcomeUnknown，保留现场。

src/ruocun/hooks/journal.py · 第 45–74 行

「原工具的收据不能替后置命令确认副作用」。查到 Write 成功就保留它，不为修复 Post 日志重新写文件。核对 Post 也查它自己的记录。一份可信收据能让调用点直接使用既有结果，不能用这种规则承诺每个遗失步骤都能自动补跑。恢复的证据顺序见 《工具可能已经执行》。

只读 CSV 验收已经得到表头和一条时间证据。如果以后要编成正式的导出验收流程，可以按谁触发、谁拿结果来选择扩展点。

需求扩展点输入和产物

06

学习效果检测

6.1 判断改参、权限和收据的生效时机

1． 两个匹配的 Pre Hook 先后返回完整的 updatedInput。第一个给 path=reports/a.md 和正文，第二个只给 path=reports/b.md，同时要求询问用户。此时应弹出哪个文件的批准框？怎么改才能对正确目标提问？

展开详答

后一个提供的参数对象整体生效，只剩 b.md 的路径。Write 缺 content，校验阶段就会反馈错误，此时没有可供批准的有效写入。让第二个 Hook 返回带 b.md 和正文的完整参数，再按实际参数重新校验并授权。

2．追踪恢复 · Write 结果已保存，Post 意图存在但日志没有可信收据，先核对谁？

展开详答

分别查原工具与 Post 的记录。Write 确认完成后保留该结果，核对 Post 是否已经登记日志，避免重复执行任何有副作用的命令。

07

模拟面试官提问

7.1 Agent 开发实习

独立核心题

一套修复流程和一个写入前检查，你会分别放哪里？

展开参考回答

“复现、修改与验证是模型要学会执行的流程，可以放进 Skill。写入前检查需要在相应事件点自动获得最终调用的相关信息，放在 Pre Hook 和权限关口。”再依据是否调用外部服务考虑 MCP。

重点追问链

Pre 重写路径后如何发现输入问题？

展开主问回答

“我会看 Hook 返回的完整参数，再沿 schema 和最终权限走一遍。”

追问 1 只返回路径会怎样？

展开追问 1 回答

它替换整个对象，必填字段缺失。

追问 2 权限拒绝而 Hook 返回 allow 呢？

展开追问 2 回答

保留拒绝。

追问 3 能从 Post 被触发断言写入符合业务要求吗？

展开追问 3 回答

先读原工具结果和实际产物，再看它覆盖的要求。

7.2 Agent harness 岗位

独立核心题

为什么 Hook 自己也要写意图和收据？

展开参考回答

“它是能产生副作用的命令。Pre 运行在工具之前，Post 运行在结果确认之后。每一个命令批都有独立身份，恢复时可以证明哪一步有结果。”原工具的确认不能说明 Hook 自己的日志、通知或外部动作是否发生。

重点追问链

保存过程中退出，怎样避免恢复时把工具和 Post 都执行两遍？

展开主问回答

“按各自意图核对。工具结果保存未确认时先停在工具边界。工具已确认而 Hook 不明时，转向核对 Hook 的实际影响。”

追问 1 Hook 有可信收据呢？

展开追问 1 回答

核对完整性后直接取结构化结果。

追问 2 命令配置与之前不同怎么办？

展开追问 2 回答

选中命令摘要参与意图身份核对，不能把新配置当旧结果使用。

追问 3 子代理启动 Hook 给的上下文保存失败呢？

展开追问 3 回答

子模型请求尚未派发，保留现场核实。

08

这一篇带走什么

Hooks 在指定事件接收输入，Pre 的改参和意见回到校验与权限，Post 在工具结果确认后用自己的意图和收据运行。

  • 扩展点能改参数时，让所有后续校验、权限与执行使用同一份最终输入。
  • 在外部副作用后继续触发新动作时，独立确认每一步。恢复时用可信收据接回已确认结果，对未知动作先核实。
  • 让模型按需拿到流程用 Skill，让模型调用外部能力用 MCP，需要在确定的事件关口插入行为时用 Hook。

原工具的结果与 Post 的收据都可以留作交付证据。把它们带回最后的任务验收，看看它们各自能证明用户要求的哪一项。
